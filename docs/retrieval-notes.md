# 普通 RAG 与 GraphRAG

**普通 RAG** 把文档切块，建关键词索引或向量索引，查询时召回最相关的几块交给模型。它回答的是局部问题，比如「PDF 规格表怎么写」。建索引只需要分块和算一次 embedding，文档改了只重算受影响的块。

**GraphRAG** 先让模型从全部文档里抽取实体和关系，建成知识图谱，再做社区聚类，给每个社区写摘要。查询时沿图谱关系或社区摘要作答，适合跨文档的全局问题，比如「这些规范有哪些共同原则」。

**成本差别。** GraphRAG 建索引时每一块都要调用模型，社区摘要还要再调一轮，费用和耗时通常比普通 RAG 高一到两个数量级。文档一变，受影响的抽取和摘要都要重做。抽取出错会沉淀进图谱，比召回错一块更难发现。

**本仓库的选择。** 语料是十几篇互相独立的规范，planner 问的都是局部问题，所以用 BM25 加向量、再用 RRF 融合的普通混合检索就够了。
