# Reviewing plans and results

## Reviewing a plan
A plan review checks that each stage has one clear goal, that stages are in dependency order, and that nothing the request asked for is missing. It is cheaper to fix a plan than a draft.

## Acceptance criteria
Write acceptance criteria that a reviewer can check without asking the author: a format, a count, a length or a property of the output. "Looks good" is not a criterion.

## Reviewing a result
A result review compares the output with the stage's acceptance criteria and its sources, not with the reviewer's personal taste. Record what was checked and what failed.

## Asking for changes
Request changes as specific edits with a reason. Group them by severity so the author fixes what blocks approval first.
